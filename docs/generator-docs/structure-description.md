# Декомпозиция input на важные данные

Структура обучающей выборки. Конкретная запись (input).

```jsonc
{
  "schema_version": "",
  /// релевантный контекст других файлов (сигнатуры, типы, секции, поддеревья).
  "retrieval_context": [],
  /// релевантный контекст текущего файла (сигнатуры, типы, секции, поддеревья).
  "current_file_context": [],
  /// история редактирования.
  "edit_history": [
    {
      // численный id.
      "id": 1,
      "path": "",
      "before": "",
      "after": "",
    },
    {
      "id": 2,
      "path": "",
      "before": "",
      "after": "",
    }
  ],
  /// текущий исходный фрагмент после истории, до предсказываемой правки.
  "edit_target": {
    "path": "",
    "code_text": "",
    // Смещения от начала code_text в байтах UTF-8, начиная с 0.
    "position_encoding": "utf8_bytes",
    // Положение пользователя в code_text.
    "cursor": {
      "offset": 0
    },
    // Границы редактируемых регионов в code_text.
    "markers": [
      {
        "id": 1,
        "offset": 0
      },
      {
        "id": 2,
        "offset": 0
      }
    ]
  },
  /// для обучения. Входной промпт.
  "input_result": ""
}
```

## Координаты курсора и маркеров

- Все `offset` внутри `edit_target` отсчитываются от начала `code_text` в байтах UTF-8, до вставки маркеров и `<|user_cursor|>`.
- Смещения находятся в пределах от `0` до длины `code_text` в байтах UTF-8 включительно и не разрезают многобайтовый символ.
- Маркеры имеют последовательные номера от `1`; их смещения не убывают. Диапазон между двумя границами трактуется как `[start, end)`.
- Курсор находится между первой и последней границами, включая их позиции.
- В шаблоне `code_text` пустой, поэтому оба маркера и курсор имеют смещение `0`. Разные маркеры в одной позиции обозначают пустой диапазон для вставки.

## Контекст релевантных файлов и текущего файла (retrieval_context, current_file_context)

Оба блока содержат релевантные структурные представления и фрагменты файлов:

- `retrieval_context` — сведения из других файлов;
- `current_file_context` — дополнительные сведения из текущего файла, например сигнатуры вне редактируемого участка.

Способ извлечения зависит от формата: сигнатуры для кода, секции (если это Markdown), элементы для HTML/XML, ветви объектов для JSON.
