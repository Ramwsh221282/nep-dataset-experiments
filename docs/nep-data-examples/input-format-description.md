# Общая структура `input`

Используется порядок **SPM: suffix → prefix → middle** (на основе zeta 2.1 формата), а не prefix → suffix → middle (родной от qwen 2.5 coder base).

Следующая строка — схема; выражения в фигурных скобках обозначают содержимое, а не буквальный текст промпта:

```text
{необязательный BOS}<|fim_suffix|>{suffix}<|fim_prefix|>{контекст и история}{заголовок текущего файла}{размеченный исходник}<|fim_middle|>
```

## Suffix

Текст между `<|fim_suffix|>` и `<|fim_prefix|>` — неизменяемый хвост текущего файла или доступного фрагмента.

- Он может быть пустым.
- В строке промпта он расположен первым, но при восстановлении исходника добавляется **после размеченной части текущего файла**.
- Это не обязательно весь текст после курсора: курсор может находиться внутри одного из редактируемых регионов, а suffix — после всех этих регионов.

## Дополнительный контекст

До заголовка текущего файла могут находиться контекстные файлы или фрагменты, например:

```text
<|file_sep|>pricing.py
...код или фрагмент контекстного файла...
```

Контекст даёт информацию о связанных функциях и предыдущих действиях. Он не является дополнительной областью, которую разрешено менять данным ответом. Одно имя файла может встретиться несколько раз, если переданы разные фрагменты.

## История изменений

Служебная секция имеет заголовок:

```text
<|file_sep|>edit_history
...история изменений...
```

В варианте с `<filename>` используется `<filename>edit_history`.

История обычно содержит изменения в формате unified diff:

```diff
--- a/pricing.py
+++ b/pricing.py
@@ -1 +1 @@
-def calculate(price, tax):
+def calculate(price, tax, discount):
```

Это **уже произошедшие изменения**, которые помогают предсказать следующий edit. Они не являются ответом модели и не должны повторно применяться как предсказываемая правка.

## Текущий файл и регионы

Последний заголовок файла перед `<|fim_middle|>` обозначает целевой исходник:

```text
<|file_sep|>checkout.py
...неизменяемый префикс исходника...
<|marker_1|>регион A<|marker_2|>регион B<|marker_3|>
```

Маркеры — **общие границы соседних регионов**:

- между `marker_1` и `marker_2` находится регион A;
- между `marker_2` и `marker_3` находится регион B;
- `marker_2` одновременно завершает A и начинает B.

Это не независимые пары `(1,2)`, `(3,4)` и не номера строк. На входе номера идут подряд, начиная с 1, каждый встречается один раз. Требуется не меньше двух границ.

До первой и после последней границы в размеченной части может быть неизменяемый код. Отдельный suffix также остаётся неизменяемым.

### 3.5. Курсор

`<|user_cursor|>` отмечает исходное положение курсора. Он находится между первой и последней границами текущего исходника, а не в истории, внешнем контексте или suffix.

**Курсор не ограничивает редактирование своей строкой:** предсказываемая правка может находиться выше, на строке или ниже него, в пределах разрешённых границ.

## 4. Полный пример `input`

Учебный пример: в связанном файле функция получила параметр `discount`; следующий edit должен обновить её вызов. Пример:

```text
<|fim_suffix|>print(result)
<|fim_prefix|><|file_sep|>pricing.py
def calculate(price, tax, discount):
    return price * (1 + tax) - discount
<|file_sep|>edit_history
--- a/pricing.py
+++ b/pricing.py
@@ -1 +1 @@
-def calculate(price, tax):
+def calculate(price, tax, discount):
<|file_sep|>checkout.py
price = 100
tax = 0.2
discount = 10
<|marker_1|>result = calculate(price, tax)<|user_cursor|>
<|marker_2|>log(result)
<|marker_3|><|fim_middle|>
```

После удаления маркеров и курсора из текущего исходника и добавления suffix исходный `checkout.py` выглядит так:

```python
price = 100
tax = 0.2
discount = 10
result = calculate(price, tax)
log(result)
print(result)
```

Контекст `pricing.py` и история не входят в этот восстановленный исходник. Последний символ промпта — конец `<|fim_middle|>`; перевод строки перед закрывающей Markdown-оградой показан только для оформления документа.

# Обязательные проверки Input

- Ровно по одному `<|fim_suffix|>`, `<|fim_prefix|>`, `<|fim_middle|>` в SPM-порядке.
- Промпт заканчивается непосредственно `<|fim_middle|>`.
- Перед suffix допустим только отсутствующий префикс или сохранённый `<[begin▁of▁sentence]>`.
- Есть заголовок текущего файла с непустым путём и ровно один заголовок истории в предшествующем контексте.
- Границы в текущем исходнике: `1, 2, …, N`, без пропусков; `N >= 2`.
- Ровно один входной курсор, внутри редактируемой части.
- В input нет `<|endoftext|>`.
- **Разрешен синтаксически недопустимый (по коду) input.** таким образом это кандидат на пример, где модель исправляет некорректный пользовательский ввод.
